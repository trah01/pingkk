# 项目网站

纯静态页面，无需安装依赖。网站图片复用仓库 `assets` 目录，由发布工作流复制到网站中。

## 本地预览

直接用浏览器打开 `website/index.html`，无需启动服务器。保留它与仓库 `assets` 目录的相对位置即可显示图片。发布工作流会自动调整图片路径。

## 发布

1. 确认页面内容后，将网站文件和 `.github/workflows/pages.yml` 提交、推送到 GitHub 的 `main` 分支。
2. 在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 在 **Actions → 发布项目网站 → Run workflow** 手动运行首次发布。后续修改网站、PNG 图片或此工作流并推送到 `main` 后，会自动更新。
4. 发布完成后访问 https://trah01.github.io/pingkk/ ，可将这个地址填入仓库 About 的 Website 字段。

下载按钮打开最新 Release，由用户选择对应系统和处理器架构的文件。

## CLI 安装脚本

`pingkk.sh` 用于 macOS / Linux，`pingkk.ps1` 和 `pingkk.bat` 用于 Windows。Pages 工作流会将三个文件复制到网站根目录。Windows 用户可下载 BAT 后双击安装；PowerShell 和终端安装命令见仓库 README。

脚本从官方下载安装包及 SHA256 校验文件，安装到当前用户目录时无需管理员权限。自建下载站时，请修改脚本中的下载地址。

服务器需直接返回脚本原文，并声明 UTF-8 编码。安装包、`SHA256SUMS.txt` 和 `version.json` 放在同一版本目录，`pingkk/latest/` 指向最新完整版本。

通用同步脚本为 `scripts/sync_website_cli.sh`，使用时通过 `PINGKK_SITE_ROOT` 指定网站根目录。运行环境需要 Linux、Bash、curl、Python 3、sha256sum 和 flock，执行用户需拥有目标目录的写入权限。具体服务器配置及定时任务由部署者自行管理。

## Google 收录

在 Google Search Console 添加网址前缀资源 `https://trah01.github.io/pingkk/`。选择 HTML 文件验证。验证文件 `google2c8c9083e41bca20.html` 已放入 `website/` 并纳入发布流程。发布后确认 `https://trah01.github.io/pingkk/google2c8c9083e41bca20.html` 可访问，再完成验证；验证完成后仍需保留该文件。

随后提交 `https://trah01.github.io/pingkk/sitemap.xml`，并在网址检查中请求编入索引。Google 不保证收录或具体收录时间。

如果更换账号、仓库名或域名，需要同步修改 `index.html` 的 canonical、社交分享地址、结构化数据和 `sitemap.xml`。
